# Принятые проектные решения (DECISIONS.md)

## Решение 1: Защита инкапсуляции через unmodifiableList
**Проблема:** Прямой возврат внутренней коллекции `items` через `getItems()` позволяет внешнему коду модифицировать заказ в обход бизнес-правил (например, добавить позицию после `confirm()`).
**Решение:** Метод `getItems()` возвращает `Collections.unmodifiableList(new ArrayList<>(items))` — неизменяемую копию списка.
**Обоснование:** Внешний код получает доступ только для чтения. Любая попытка модификации вызывает `UnsupportedOperationException`. Это реализует принцип инкапсуляции: объект сам контролирует своё состояние, а не полагается на дисциплину внешних вызывающих.

## Решение 2: Динамический расчёт итоговой суммы вместо хранения в поле
**Проблема:** Хранение `total` как отдельного поля требует синхронизации при каждом изменении состава заказа. При ошибке синхронизации (например, забыли пересчитать после `addItem`) сумма становится недостоверной.
**Решение:** Метод `calculateTotal()` вычисляет сумму динамически при каждом вызове, проходя по всем позициям.
**Обоснование:** Итоговая сумма всегда соответствует фактическому составу заказа — невозможно рассогласование. Цена вычислительной операции ничтожна для разумного числа позиций. Это соответствует принципу "единственного источника истины" (Single Source of Truth).
